# Examples

Frozen output of paperextract on a real paper, so the input and the result
can be compared side by side without installing anything. The files are
not regenerated by the tests or the documentation build.

## geib-2019-copra

| | |
| --- | --- |
| Input | [`optica-6-4-495.pdf`](geib-2019-copra/optica-6-4-495.pdf), 11 pages |
| Output | [`Geib_2019_CommonPulseRetrieval/`](geib-2019-copra/Geib_2019_CommonPulseRetrieval/), the published paper folder |
| Start with | [`paper.md`](geib-2019-copra/Geib_2019_CommonPulseRetrieval/paper.md) and [`diagnostics/review.md`](geib-2019-copra/Geib_2019_CommonPulseRetrieval/diagnostics/review.md) |
| Walkthrough | [Worked example](https://paperextract.readthedocs.io/en/latest/tutorial.html) in the manual |

N. C. Geib, M. Zilk, T. Pertsch and F. Eilenberger, "Common pulse retrieval
algorithm: a fast and universal method to retrieve ultrashort pulses,"
*Optica* **6**, 495–505 (2019),
[doi:10.1364/OPTICA.6.000495](https://doi.org/10.1364/OPTICA.6.000495).

It was chosen because it has what makes scientific extraction hard: 28
numbered equations, four tables of operators written in mathematics, eight
multi-panel figures and a text layer that loses some mathematical glyphs.

It was produced on 24 September 2026 on an Apple silicon Mac with
paperextract at commit `b7ba984` (just after 0.1.0, so the records report
`0.1.1.dev1`), MinerU 4.0.5 with llama.cpp, and figure descriptions from
Qwen3.8-27B through the local MLX worker:

```sh
uv run paperextract optica-6-4-495.pdf --library library
uv run paperextract describe --backend mlx --all --library library
```

Records name the directories used on that machine, so they contain paths
such as `/Users/Shared/paperextract-example/`.
